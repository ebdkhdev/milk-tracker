# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Milk Tracker" (formerly "Suivi lait") is a French / English / Arabic PWA for logging a baby's bottle feeds. It is a React + TypeScript app built with TanStack Start (Vite) in **SPA mode**: all data lives in the browser (IndexedDB / localStorage) and the app works fully offline (system fonts only). The build output is a static site plus one Vercel Function, `api/sync`, used only by the optional sharing between parents (Neon Postgres); without a family the app never calls it. The last pre-React version (single `index.html`) is tagged `v1.0.0`.

## Commands

```
npm install
npm run dev          # dev server on http://localhost:3000 (no service worker in dev)
npm run typecheck    # tsc --noEmit
npm test             # build, then the end-to-end suite in headless Chrome (tests/)
node --env-file=.env.local scripts/migrate.mjs   # create/update the sharing schema in Neon (idempotent)
npm run build        # vite build + scripts/build-sw.mjs -> dist/client (static site)
python3 -m http.server 8000 -d dist/client   # serve the production build (needed to test the service worker)
```

There is no linter. `npm test` runs `tests/run.mjs` against `dist/client` in a local headless Chrome (set `CHROME_PATH` if it is not found; no npm dependencies): server protocol (`api`, no browser), main flow, backup, age-based minimum, iOS install hint, layout (touch targets, 200% text, 320px), WCAG contrast (colours parsed from `src/styles.css`, glass panels measured on the rendered backdrop pixels), the upgrade from `v1.0.0` (needs the git tag), several babies including a phone on a real v2.8.0 build in the same family and the IndexedDB v3 → v4 upgrade (`tests/lib/oldbuild.mjs` builds a tag once into the temp dir), and sharing between two phones (two Chrome profiles in turn). The test server answers `/api/sync` with the real `api/_core.mjs` over an in-memory store (`tests/lib/memory-store.mjs`, same rules as the Postgres store); tests never touch the real database. Run one suite with `node tests/run.mjs <name>`. GitHub Actions (`.github/workflows/test.yml`) runs `npm test` on every push and pull request (Chrome gets `--no-sandbox` when `CI` is set; failed checks are also printed as `::error` annotations, visible on the run page without the logs). `vite.config.ts` pins `preview.host` to `127.0.0.1`: the build's prerender step fetches from that address, and on Linux the preview server would otherwise listen on IPv6 only and the build fails. To reproduce CI locally: run the suite in the `mcr.microsoft.com/playwright` Docker image with `CHROME_PATH` pointing at its Chromium. Every check is an assertion and the run exits non-zero on failure; add checks there when you change behaviour.

Deploy to production (project is already linked via `.vercel/project.json`):

```
npx vercel deploy --prod --yes
```

Vercel builds the project itself: `vercel.json` sets `framework: null`, `npm ci`, `npm run build` and `outputDirectory: dist/client`.

Production URL: https://suivi-lait.vercel.app (the Vercel project keeps its old name on purpose: users' data is tied to this origin, so changing the domain would leave them with an empty app). Deployment Protection (Vercel Authentication) is deliberately disabled on the project so the link is public; do not re-enable it.

## Architecture

**Layout.** `src/routes/__root.tsx` is the HTML shell (head/meta, manifest, fonts). `src/routes/index.tsx` is the only route and holds all app state (`App`). UI pieces are in `src/components/`, React hooks in `src/hooks/`, logic in `src/lib/` (`db.ts` IndexedDB, `i18n.ts` strings, `format.tsx` language/unit context, `settings.ts` localStorage + constants, `reminder.ts`, `dates.ts`). Styles are plain CSS in `src/styles.css` (class names and element ids are the same as in v1.0.0). Static files (`manifest.webmanifest`, icons) are in `public/`. `src/routeTree.gen.ts` is generated by the router plugin; do not edit it.

**Client-only rendering.** SPA mode prerenders only the shell to `dist/client/index.html` (`vite.config.ts`). The `/` route has `ssr: false`, `wrapInSuspense: true` and renders `App` inside `<ClientOnly>`: this combination makes the first client render match the empty prerendered boundary (otherwise React throws hydration error #418). Anything touching `window`, `localStorage`, `indexedDB` or `navigator` must only run inside `App` or its children, never at module top level or in `__root.tsx`.

**Legacy identifiers.** The storage keys below (`suivi-lait-db`, `suivi-lait-unit-v1`, `suivi-lait-reminder-v1`, `suivi-lait-lang-v1`, `suivi-lait-baby-v1`, `suivi-lait-data-v1`) keep the old name deliberately (newer keys such as `suivi-lait-ios-hint-v1`, `suivi-lait-quick-v1`, `suivi-lait-milk-v1`, `suivi-lait-backup-v1`, `suivi-lait-sync-v1`, `suivi-lait-device-v1`, `suivi-lait-push-v1`, `suivi-lait-babies-v1` and `suivi-lait-current-baby-v1` use the same prefix for consistency). Renaming them would orphan existing users' data. Do not rename them.

**Data model.** IndexedDB database `suivi-lait-db` (version 4) with five object stores; every record written locally carries `updatedAt` (ms), used by sharing to resolve conflicts:
- `feeds` (keyPath `id`, index `by_date` on `date`): one record per bottle, `{ id, date: "YYYY-MM-DD", ml: number, time: ISO string, type?: "formula" | "breast", note?: string }`. `type` and `note` are optional (no index, no schema bump): older records have neither, and a type is never guessed for them. Millilitres are the canonical unit; ounces are a display-only conversion (`ML_PER_OZ = 29.5735`).
- `daily` (keyPath `date`): one record per day for per-day flags, currently `{ date, vitaminD: boolean, vitaminDTime: ISO string | null }`. Add new per-day facts here rather than creating more stores.
- `days` (keyPath `id` = `babyId|date`, v4): the per-day records of the babies other than the first.
- `events` (keyPath `id`, index `by_date`, v4): diapers, sleep and growth (any baby, `babyId` absent for the first).
- `outbox` (keyPath `k` = `kind:key`, v3): changes waiting to be sent to the family, `{ k, kind, key, data, deleted, updatedAt }`. Only filled while the device is in a family.

The chosen unit is persisted in `localStorage` under `suivi-lait-unit-v1`.

**Daily minimum (depends on the baby's age).** The minimum for a day comes from `minimumFor(baby, dateStr)` (`lib/baby.ts`). Baby settings live in `localStorage` under `suivi-lait-baby-v1` (`{ birthDate: "YYYY-MM-DD" | null, tiersMl: number[] }`) and are edited in the ⚙ panel (`components/BabySettings.tsx`). The age bands are fixed (`TIER_STARTS`, in completed months: 0, 1, 2, 4, 6+); only their values are editable, with indicative defaults in `DEFAULT_TIERS_ML`. Each day uses the baby's age **on that day**, so past days keep the minimum of the age they had. Without a birth date every day uses `DAILY_MIN_ML = 600`, so existing users see no change. The minimum drives the progress ring and status line in the total card (`--warn` orange while under, `--good` green once reached), the "reached" stats, and the per-row marker in the history (`DayRow.minMl`). History bars are scaled to `max(totals, minima) * 1.1` so markers never sit on the edge. When the minimum varies within the period, labels switch to generic wording (`statDaysReachedVar`, `historyLabelVar`).

**Migration.** On boot, `migrateFromLocalStorage()` imports any data from the pre-IndexedDB key `suivi-lait-data-v1` and then deletes that key. Keep this path working if the schema changes. If you change the IndexedDB schema, bump `DB_VERSION` and handle it in `onupgradeneeded`.

**State and data flow.** `App` keeps the settings (lang, unit, reminder, baby, quick amounts, milk prefs…), `viewDate`, `editingId` and `period` in React state and wires the components; the rest lives in hooks (`src/hooks/`): `useData(dateStr)` migrates legacy data, then reads the viewed day and all records from IndexedDB and exposes `reload()`; `useClock()` gives `now` (every minute and on foreground); `useToast()`; `useSharing()` holds the family state and actions. Every local write ends with `bump()` (= `reload()` + clock refresh). Derived data: `buildRows()` (Stats.tsx) for the period, `lib/feedText.ts` for the "last bottle" / rhythm sentences. Always change the viewed day through `goToDate()`, which clamps to today, clears edit mode, and pre-fills the past-day time input.

**Several babies.** The first baby (`FIRST_BABY = "b1"`) keeps exactly what existed before: feeds without `babyId`, the `daily` store, its settings in `suivi-lait-baby-v1`, and sync kinds `feed` / `daily` / `baby`, so phones still on v2.8.0 in the same family keep working. Other babies' feeds carry `babyId` and sync as `bfeed`, their vitamin D lives in `days` (kind `day`); every baby's name and sex, and the other babies' settings, are profiles (`suivi-lait-babies-v1`, kind `profile`; the first baby's profile carries name and sex only, because v2.8.0 rewrites kind `baby` without unknown fields). Older apps ignore the kinds they don't know (checked by a test with a real v2.8.0 phone). The selected baby is per phone (`suivi-lait-current-baby-v1`); `App` derives that baby's feeds, day records, minimum, stats, rhythm, report and backup suggestions from everything `useData()` loads. The header shows a baby selector only with two babies or more. Removing a baby (never the first) deletes its records through the normal delete paths (tombstones reach the other phone) and the profile. Push: vitamin D counts as given when every baby had it (phone report and server family check); the family "next bottle" follows the selected baby's rhythm (fine for twins fed together); partner notifications name the baby when the family has several. Backups carry `profiles`, `days`, `events` and feeds' `babyId`; older files go to the first baby.

**Quick-add amounts.** The four quick buttons come from `loadQuick()` (`suivi-lait-quick-v1`, ml, defaults `QUICK_AMOUNTS_ML`) and are edited in ⚙ like the age bands (uncontrolled inputs keyed on unit + value, committed on blur/Enter, unchanged display values ignored so oz round-trips never drift). `suggestQuick()` proposes the four most frequent amounts of the last 14 days. Backups carry them; import adopts them only if this device still has the defaults.

**Milk type and notes.** Recording the milk type is opt-in (⚙, `suivi-lait-milk-v1` = `{ track, last }`). When on, a Formula / Breast milk segmented control sits next to "Ajout rapide" and every new bottle takes `last`. Rows show the type as a badge and the note under the amount; both are edited in `EditItem` (note trimmed, max `NOTE_MAX` chars, emptied note removed). The stats add a "breast milk (by volume)" tile computed over typed bottles only (`DayRow.breastMl / typedMl`). Import validates both fields.

**Feeding rhythm.** `lib/rhythm.ts`: `averageInterval()` averages the gaps between consecutive bottles (sorted by time across days), leaving out gaps over `GAP_MAX_MIN` (8 h, taken as unlogged bottles) and under `GAP_MIN_MIN` (10 min, a top-up), and needs `MIN_INTERVALS` (3) usable gaps. `feedingRhythm()` uses the last 24 h, falling back to 7 days, and gives the next bottle as last + average; the total card shows "Toutes les … en moyenne · prochain vers HH:MM" (or "attendu depuis" once that time has passed), today only and hidden 24 h after the last bottle. The stats show the period's average interval as a tile.

**Tabs.** A bottom tab bar (`components/TabBar.tsx`, ids `tab-<name>`) switches between Bottles (day view), Diapers, Sleep, Growth and Stats (stats, history, report button); `App` keeps `tab` in state and `setTab()` also leaves the report and edit mode. The bar is glass (functional layer), padded with `safe-area-inset-bottom`; `.wrap` and the toast are offset above it. Labels are capped at 13px (iOS tab bars don't scale with Dynamic Type). A history row opens its day on the Bottles tab. Tests switch tabs with `b.tab(name)`, and the layout test measures touch targets on every tab.

**Paediatrician report.** The "Résumé pour le pédiatre" button under the history opens `components/Report.tsx`, which replaces the main view (not an overlay; focus goes to its title and back to the button on close). Its figures come from `summarize()` in `Stats.tsx`, the same function as the stat tiles, so they always match. It lists one row per day of the period (chronological), the notes, and offers "Imprimer ou PDF" (`window.print()`; the `@media print` block shows only the sheet, forces light colours and removes the backdrop and every `backdrop-filter`) and "Partager en texte" (`navigator.share`, clipboard fallback), which works even where printing doesn't.

**Undo, last bottle, toasts.** `removeEntry` deletes right away, then `showToast()` offers "Annuler", which `dbPut`s the same record back (same id and time); only the latest deletion is undoable, for 6 s. `components/Toast.tsx` is a bottom glass toast inside an always-mounted `role="status"` live region, also used for backup results. The total card shows "Dernier biberon il y a …" (`lastFeedText` in `routes/index.tsx`) from the most recent feed of any day, only when viewing today, hidden after 24 h, ignoring feeds in the future; `bump()` also refreshes `now` so a feed just added never looks ahead of the clock.

**Backup.** The ⚙ panel has Export / Import (`lib/backup.ts`). Export builds `{ app: "milk-tracker", version: 1, exportedAt, feeds, daily, baby }` from the data already in state and calls `navigator.share` with a file on touch devices (iCloud Drive, mail) or downloads it elsewhere; it must stay synchronous inside the click, because Safari refuses `share()` after an `await`. Import validates every row (date, ml, time), skips and counts bad ones, merges with `dbImport` (one transaction over both stores, `put` so re-importing never duplicates), and takes the file's baby settings only when this device has no birth date yet (a new phone), so an old backup never overwrites current settings. On boot the app calls `navigator.storage.persist()` (best effort). A successful export records its date in `suivi-lait-backup-v1` (`{ last, snoozeUntil }`); `backupDue()` shows a reminder banner when there is data and the last export is over 30 days old, or, with no export recorded, once the oldest bottle is 14 days old; "Plus tard" snoozes it for 7 days. Only one banner shows at a time: the backup reminder wins over the install hint.

**Install hint.** Chromium fires `beforeinstallprompt` (the "Installer" banner); Safari never does, so on iOS/iPadOS outside standalone mode `InstallBanner` shows written instructions instead, dismissable and remembered in `suivi-lait-ios-hint-v1`. Installing matters on iOS: Safari may evict a non-installed site's storage after weeks without use.

**Past days and editing.** Feeds added while viewing a past day take their time from the `#custom-time` input (shown only when `.custom-row` has the `past` class); today uses the current time (see `addEntry`). `editingId` puts one feed item into inline edit mode (`EditItem`: amount in the current unit + HH:MM), saved through `updateEntry()` which rewrites the record via `dbPut`. The day label opens a hidden `<input type="date">` and history rows call `goToDate()`.

**Statistics.** `App` groups all records by date into `DayRow`s for `period` (7 or 30 days); `components/Stats.tsx` renders the tiles and the history. Averages are computed over days that have at least one feed ("jours renseignés"), not over the whole period; vitamin D is counted over the whole period. The "next day" button is hidden when viewing today.

**Vitamin D reminder.** Settings live in `localStorage` under `suivi-lait-reminder-v1` (`{ enabled, time: "HH:MM", lastNotified: "YYYY-MM-DD" }`), so they are per device. The `now` state ticks every minute and on visibility change; `due` is true once the reminder time has passed and today's vitamin D is not given, which adds the `due` class to the card (when viewing today) and fires at most one browser notification per day (via the service worker's `showNotification` when available). There is no push backend: notifications only fire while the app is open. As the app-closed fallback, the "Google Agenda" link (`buildGoogleCalendarUrl`) opens a daily event (`RRULE:FREQ=DAILY`, in the device's time zone) as a Google Calendar template in a new tab; the alert is the calendar's default one. (Up to v2.1.1 there was also a downloadable `.ics` link; it was removed because desktop browsers only save it as a file.) The service worker handles `notificationclick` by focusing or opening the app.

**Sharing between parents.** Optional, opt-in in ⚙. A phone creates a family and gets a 26-character code (128 bits, generated server-side; only its SHA-256 is stored); the other parent pastes it in ⚙ › Partage (no QR or link: on iOS those open Safari, whose storage is separate from the installed app). Joining or creating queues the whole local history (`dbQueueAll`), so both histories merge.
- Client (`lib/sync.ts`, state in `suivi-lait-sync-v1` = `{ code, cursor, lastSync }`): while in a family, `db.ts` writes the change to `outbox` in the same transaction as the record (`setQueueing`); `syncNow()` posts the outbox in chunks of 500 to `POST /api/sync` (code in the `X-Family-Code` header, never in a URL), acks what was sent, applies what the other phones changed since `cursor` (`dbApplyRemote`, which never queues) and repeats until both sides are drained. Syncs run on start, on foreground/online, every minute while visible, and 1.5 s after a local write. Offline, changes simply stay queued.
- Conflicts: last write wins on `updatedAt`, decided by the server and re-checked locally; deletions are tombstones. Every local write is stamped now, so undo (re-putting a deleted bottle) beats the propagated deletion. Imports keep a local record unless the file's copy is newer and give added records the file's timestamp (0 if none), so an old backup never overrides the other parent. The server clamps `updatedAt` to its clock + 5 min.
- Who added a bottle: in a family, each phone can set a name (⚙ › Partage, `suivi-lait-device-v1`); new bottles get `by: name`, shown under the row and in the report notes. It is set on add only and kept through edits.
- Shared: feeds, daily records and the baby settings (`kind: "baby"`; on create/join they are sent with time 1 if a birth date is set, else 0, so joining never erases the family's birth date). Per phone: language, unit, quick amounts, milk-type preference, reminder. Leaving keeps all local data and only stops sharing; the family stays on the server. "Effacer les données partagées" (two-step confirmation in the panel) sends `{ action: "delete" }`, which deletes the family and, by cascade, all its records, then leaves. The other phone gets a 404 at its next sync (`status: 'gone'`), leaves on its own with a message, and keeps its local data.
- Server: `api/sync.mjs` (Web `POST` handler) → `api/_core.mjs` (protocol, validation, codes; files starting with `_` are not functions) → `api/_pg.mjs` (`pg` pool with `attachDatabasePool`, pooled `DATABASE_URL`). Abuse limits (`LIMITS` in `_core.mjs`, fixed windows in the `rate_hits` table, IPs and codes only as hashes): 10 family creations per hour per IP, 600 requests per 10 min per IP and per family; over that the API answers 429 and the client just retries at the next sync. Each sync locks its family row (`FOR UPDATE`) so per-write sequence numbers commit in order and no client skips a row. Schema: `scripts/migrate.mjs` (direct `DATABASE_URL_UNPOOLED`). The function runs in `fra1` (`vercel.json` `regions`), next to the database (Frankfurt). Env vars come from the Neon Marketplace integration (`vercel env pull`); production, preview and development all use the same database, so a preview deploy writes real data.
- The service worker never handles `/api/`.

**Push notifications (app closed).** Opt-in per phone in ⚙ › Notifications (`components/NotificationSettings.tsx`, `lib/push.ts`, state in `suivi-lait-push-v1` = `{ token, enabled, nextFeed, partner }`). On iOS they only exist for the installed app, so a Safari tab gets an explanation instead. Enabling asks for permission inside the tap (iOS requirement), subscribes with the server's VAPID public key and posts the subscription; the app then re-posts it on every start (iOS may replace it silently) and sends `update`s 2 s after anything the server depends on changes: language, unit, time zone, name, the vitamin D reminder switch/time (vitamin D push follows that switch, no second setting), "given today", and the last bottle + expected next one (`feedingRhythm`). `refreshPush`/`updatePush` re-read the stored state, so a pending update never re-subscribes a phone that was just turned off. The in-app reminder notification is skipped when push covers it. Enabling sends the reminder time, time zone, name, "given today" and the last bottle time to the server (said in the intro text and the footer, `footerPush`). The phone sends `X-Device-Token` (random, only its hash stored) on `/api/push` and `/api/sync`, plus the family code.
- Server: `api/push.mjs` → `api/_push.mjs` (`handlePush`), rows in `push_subs` (family link `ON DELETE SET NULL`). `api/_qstash.mjs` keeps QStash in step: a schedule `vitd-<id>` with `CRON_TZ=<tz> m h * * *` per phone, and one delayed message for the next bottle (per family when in one, so the partner's bottle reschedules it for both; per phone otherwise), the previous one cancelled best effort. QStash calls `api/push-fire.mjs`, which verifies the signature on the raw body and URL, then `handleFire` decides at fire time: skip if vitamin D was given today in the phone's time zone (in a family: on any phone, from `records`), skip a stale or superseded next-bottle message, skip removed subscriptions. In a family, when a bottle newer than the scheduled one exists (logged on a phone without notifications), the fire reschedules from it with the same interval instead of dropping the reminder; an `update` from a phone that hasn't synced the latest family bottle is ignored. `{ action: "test" }` (« Notification de test » in ⚙) pushes to the asking phone right away. iOS revokes subscriptions that get pushes without a notification, so the service worker always shows what it receives and every decision is on the server. `api/sync.mjs` also pushes "X a ajouté un biberon" to the family's other opted-in phones for genuine inserts (`xmax = 0`), at most 3 fresh ones per sync (a join snapshot or import is not news), after responding (`waitUntil`). Expired subscriptions (404/410) are deleted.
- Only production creates real QStash schedules/messages (`VERCEL_ENV === 'production'`; previews share the database) and they always target the production URL. Env: `QSTASH_*` (Upstash Marketplace integration), `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` (sensitive, server only, never `VITE_`). Tests use `memoryPushStore`, `fakeScheduler`, `fakeSender` (`tests/lib/memory-store.mjs`); a real push to a real phone can only be checked by hand.

**Offline / PWA.** `src/sw.js` is a template: after `vite build`, `scripts/build-sw.mjs` fills in the list of built files (hashed asset names) and a cache name `milk-tracker-<hash of the build>`, and writes `dist/client/sw.js`. The cache name changes on every build that changes a file, so old caches are purged on activate; there is nothing to bump by hand. The worker must stay at `/sw.js` with scope `/` (existing installs point there) and is registered only in production builds. It uses network-first for navigations (falls back to cached `/index.html`) and cache-first for everything else. `vercel.json` sets `Cache-Control: no-cache` on `sw.js` so updates are picked up, and sets the manifest content type.

**Design (Apple HIG).** The UI follows Apple's Human Interface Guidelines (iOS grouped-list look). Tokens are CSS custom properties on `:root` in `src/styles.css`, with dark values applied both via `prefers-color-scheme` and via `[data-theme="dark"]`. Rules to keep:
- Colour roles: `--tint` (indigo) is for interactive elements only; `--good` (green) means minimum reached / given; `--warn` (orange) means not reached / reminder due; `--danger` for delete. Never reuse a colour for another meaning, and always pair status colour with text or a glyph (✓, ⏰).
- Every text colour was checked for WCAG contrast >= 4.5:1 on the surfaces it sits on (opaque surfaces, glass panels and the backdrop), in light and dark. Re-check any new or changed colour pair before using it.
- Type uses the system font (`--font`, SF on Apple devices) and `--font-rounded` for numbers, sized in `rem` from a 17px base. On Safari, `html { font: -apple-system-body }` makes the whole layout follow the user's Dynamic Type size, so use `rem`, never `px`, for text, and keep layouts working at 200% (grids use `auto-fit`, rows may wrap).
- Touch targets are at least 44×44px (a 36px visual control gets an `::after` overlay to reach 44).
- Glass everywhere (a deliberate choice of the user, beyond Apple's advice to keep Liquid Glass to the functional layer): a fixed colour backdrop (`body::before`, `--blob-*` radial gradients over `--bg`; a pseudo-element because iOS ignores `background-attachment: fixed`) sits behind the page, every card and tile is a translucent `--panel` with `backdrop-filter`, and the top bar has no solid fill: `header::before` is a scroll-edge band (blur + fade, padded with `env(safe-area-inset-top)` because the PWA uses a translucent status bar) with the three header controls as glass capsules (`--glass*`). Keep blur/mask off `<header>` itself, it would become the backdrop root of the capsules. The switch thumb turns to glass while pressed. Secondary text that sits directly on the backdrop (section labels, notes, footer) uses `--label-on-bg`, which is darker/lighter than `--label-2`. Contrast was measured on the real backdrop pixels (worst pixel, after the panel's `saturate(1.8)` and fill); if you change a blob, the panel opacity or a text colour, re-measure. `prefers-reduced-transparency` (Chromium only; Safari has no such query, so legibility must hold without it) and `prefers-contrast: more` make the panels, band and capsules opaque; `prefers-reduced-motion` disables transitions.
- Use logical properties (`margin-inline-start`, `inset-inline-start`, `border-block-start`, `text-align: end`) so Arabic mirrors correctly; the progress ring is mirrored in RTL.
- `theme-color` (in `__root.tsx`) and the manifest colours match `--bg`.

**i18n.** All UI strings live in the `STRINGS` dictionary (`fr`, `en`, `ar`) and are read through `t(key, vars)`; never hardcode user-visible text. `{name}` placeholders are substituted from `vars`; a value can also be an object of `Intl.PluralRules` categories (`one`, `two`, `few`, `many`, `other`) selected by `vars.n` (Arabic needs `two`/`few`). Missing keys fall back to French. Components get `t`, `locale` and the unit helpers from `useFormat()` (`lib/format.tsx`); `App` sets `<html lang dir>` in an effect. The language is stored in `localStorage` under `suivi-lait-lang-v1`; without it, users who already have unit/reminder settings stay in French and new users get their browser language. Dates use `LOCALES` (`ar-u-nu-latn` keeps Western digits). Units are displayed via `unitLabel` / `formatAmount()` (`مل` / `أونصة` in Arabic). Arabic switches the page to RTL: use logical CSS properties (`margin-inline-start`, `inset-inline-start`, `text-align: end`), not left/right. Arabic uses the system's Arabic font.
